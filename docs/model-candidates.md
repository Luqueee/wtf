# Local GGUF candidate tournament — development families only

The selected **experimental** interpreter remains opt-in; none of these candidates demonstrated a convincing new supported explanation on the nine development cases. This is not a promotion decision or external blinded test. The corresponding visible and JSON reports are in `scripts/lab/artifacts/dev/run-20260926T220628.201559Z-1376969/evaluations/` (three named run directories below); snapshots come from **nine real single-execution fixture failures/outcomes**, not model-generated error strings. The reserved families were not inspected for this selection.

All three available weights were downloaded in a private cache, total **6,534,459,264 bytes**, under the pre-set 8 GB download ceiling; each download completed in under 23 seconds (pre-set 20-minute per-file limit). No user secrets or reserved snapshots were sent to the model. The upstream cards state the license and native context; product context was capped at **2,048 tokens**, output at **192 tokens**, temperature 0. Runtime: locally built CUDA-enabled llama.cpp `llama` unified frontend, version **0.5.0-dev commit 9588757**, executable SHA-256 `88adb7ef4d10b1b60f59db5e0f232fce3a13d6ce595506eb731b1ee78f50e5af`; GGUF v3. The three GGUF checksums were calculated locally and the Phi checksum was cross-checked against [the repository LFS metadata](https://huggingface.co/api/models/bartowski/microsoft_Phi-4-mini-instruct-GGUF/tree/main?recursive=true). Qwen/Granite use third-party conversions; do not confuse them with differently hashed official quantizations.

GPU: RTX 4060 Ti 8,188 MiB (reported usable ~8,188), device total `memory.used` polled through `nvidia-smi` approximately every 50–100 ms. During the final forced-maximum measurement other processes occupied **13 MiB** before loading each candidate. `python3 scripts/lab/measure_models.py --runtime PATH --model GGUF --snapshot scripts/lab/artifacts/dev/<run>/tar-malformed-archive.snapshot.json --output FILE` forced 192 generated tokens (`finish_reason=length`) and recorded 192/203/264 prompt tokens respectively for Phi/Qwen/Granite. The 2,048-token context is the configured KV limit, not a claimed measured 2,048-token prompt. Full load/prefill/generation samples and usage are in `scripts/lab/artifacts/dev/{phi,qwen,granite}-memory.json`; sample polling could miss a shorter spike, so peaks are observed sample maxima, not hardware guarantees. All observed totals are below 4 GB and the 5 GB absolute cap in this configuration. A larger model or more concurrent processes are not covered.

**Historical GPU comparison only:** these three measured GGUF files stayed below 4 GB total observed device memory on this machine, but an arbitrary larger GGUF was never covered by a hard 5 GB quota. After this tournament, the opt-in CLI was changed to request llama.cpp `--device none` for every model, including unmeasured paths. Supported runtimes therefore do not offload model weights to the GPU; this is a device-selection policy, not a cap on host RAM, third-party process VRAM or arbitrary user-supplied executables. The separately measured CPU-only Phi sample below reflects the higher latency; the preceding GPU and cold-start measurements are **not** representative of the new CPU-only CLI mode.

Baseline and candidate reports share each saved, redacted snapshot. Family IDs and oracle facts were fixed before inference. “Supported new” requires more than a paraphrase of stderr or a check that merely restates it. Five cases have informative failure output. Phi and Qwen produced a syntactically valid, evidence-ID-valid tentative text on all five, but **0/5 new supported explanations or discriminating NEXT**, and **1/5 false explanation** each in the adversarial case. Granite yielded **5/5 invalid evidence references**, no added claims. No privacy incident or model-driven command execution was observed in these replays; the fake token was masked in the saved snapshot. A valid `stderr` reference did **not** make the fake permission claim true. Direct observation of this failure is why neither Phi nor Qwen is promoted. Phi is selected solely as the **opt-in experimental comparator** for reserved replay: among these weak candidates it followed the output schema more consistently than Granite, and it does not require Qwen-specific thinking switches. A favorable held-out result would still need scrutiny of the adversarial regression; no model is the product default.
